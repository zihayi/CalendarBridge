# Wi-Fi 自动发现与配对

## 发现

手机在 Wi-Fi 网络上向 UDP 8767 发送 `calendarbridge-discover` v1 请求，携带随机 16 字节 nonce（小写十六进制）。接收端单播响应，回显 nonce，提供电脑名、HTTPS 端口、证书 SHA-256 指纹和是否正在接受配对。

发现响应不含密钥。手机使用报文来源 IPv4 作为电脑地址，只接受局域网地址；已配对手机仅寻找原证书指纹，通过固定指纹 TLS 和已保存的访问密钥验证成功后，才更新 IP/端口。换地址不会重置用户的写入授权。

## 首次确认

发现本身不可信，首次配对需要两端核对验证码，由电脑本机管理员接口批准。流程：

1. 本机管理界面以独立 adminToken 调用 `/desktop/pairing/open`，开启 120 秒窗口。
2. 手机生成随机 32 字节 secret，首先只提交 `SHA256(secretHex)` 承诺值和设备信息到 `/pair/begin`。
3. 服务器生成随机请求 ID 和随机 32 字节 nonce，冻结本次会话并返回。重复的同一承诺请求只返回原挑战。
4. 手机缓存挑战，再向 `/pair/reveal` 揭示 secret。服务器校验承诺，不能修改已建立的挑战。
5. 两端分别计算 `SHA256("CalendarBridge-pair-v1\0" + id + "\0" + certificateSha256 + "\0" + nonce + "\0" + secretHex)`，取前四字节大端无符号整数模 1,000,000，补齐为六位。**手机自行计算，不接受网络返回的验证码。** 证书身份纳入比较，先承诺后揭示避免收到验证码后离线挑选随机量进行替换。
6. 用户核对手机和电脑显示相同验证码，在电脑批准。`/pair/finish` 必须携带原 secret，只有已批准且未过期的会话才能取得手机 token；adminToken 永不传给手机。

所有配对 HTTP 请求都使用固定发现指纹的 HTTPS；短码人工比较将初始发现的未认证身份绑定到用户眼前的电脑。配对请求受大小、来源、窗口时间和次数限制；每个窗口最多 8 个新承诺。拒绝、过期、错误承诺或未批准会话均不能取得 token。服务已绑定另一台手机时拒绝新设备配对。

配对只授权读取连接。新增和修改仍需要手机单独开启编辑开关，使用已有的幂等日志、原值检查和回执确认机制。

## 进程和配置

WallNote 从自身数据目录加载内置服务配置。首次启动生成独立证书和两类密钥；后续重用身份。服务通过标准输出报告无密钥的就绪信息，桌面主进程从私有配置文件加载 adminToken。

服务使用系统分配的 HTTPS 端口，避免占用旧服务；UDP 发现端口固定。标准输入关闭或收到 `stop` 时退出。配置和日历数据不随程序打包。自动集成测试使用独立目录、回环地址和随机 UDP 端口，不广播测试服务到真实 Wi-Fi。
